## Чітке виділення вибраних опцій мінікаталогу — 18.07.2026

- Неактивні текстові вибори каталогу мають білу або дуже світлу поверхню без
  сірих обводок.
- Наведення: легкий підйом, делікатна тінь і акцентний колір тексту.
- Обраний варіант: тонка внутрішня графітова лінія `1.5 px`, білий фон і
  легка тінь. Це спільне правило для BTU, візерунків, способів вимірювання,
  кришки, доставки та інших опцій; окрема крапка-позначка не використовується.
- Для кольорів збережено окреме виділення круглої плашки з позначкою, бо воно
  одразу показує вибраний відтінок. Плашки виконані у пласкому 2D-стилі: без
  внутрішнього білого блиску, тіней і об'ємних кілець.
- Основні кнопки дій лишаються темними й виразними, але також без обводки.
- Помилка у виборі дати як і раніше позначається червоним, тепер через
  внутрішню червону лінію без повернення сірої рамки.

## Що зроблено

### 1. Файл візерунку: тільки власнику, без автоматичного пересилання підряднику

Файли:
- `public/index.html`
- `api/order.js`
- `google-apps-script-v2.js`

Логіка:
1. У формі файл із `patternFile` тепер перед відправкою читається через `FileReader`.
2. У payload замовлення додається `pattern_file`:
   - `name`
   - `type`
   - `size`
   - `data` base64 без data-url prefix.
3. Ліміт файлу на клієнті: 4 МБ (`MAX_PATTERN_FILE_BYTES`).
4. `/api/order.js`:
   - додає назву файлу в Telegram-повідомлення власнику;
   - після основного `sendMessage` надсилає файл власнику через Telegram `sendDocument`;
   - результат пише в `results` як `tg_file:ok` або `tg_file:err`.
5. `google-apps-script-v2.js`:
   - НЕ зберігає файл у Google Drive;
   - НЕ зберігає Telegram `file_id`;
   - НЕ пересилає файл у тему/групу підрядника при статусі `В роботі`;
   - у `AF` пише тільки назву файлу і примітку, що файл прийшов власнику в
     Telegram, а підряднику його треба переслати вручну.

Важливо:
- Це мінімальна JSON-реалізація. Для великих DWG/DXF потрібен окремий upload endpoint або пряме завантаження в Drive/Blob.
- Поточний ліміт 4 МБ обраний, щоб не впертися в body size `/api/order`.

### 2. Власницькі Telegram-сповіщення

Файл:
- `google-apps-script-v2.js`

Додано:
- `TG_OWNER_CHAT` як окремий Script Property для чату власника.
- `TG_CHAT` лишився legacy fallback.
- При зміні статусу в колонці `C` власнику йде коротке повідомлення:
  - номер замовлення;
  - новий статус;
  - клієнт;
  - телефон;
  - дата доставки, якщо є.
- При зміні чекбоксів:
  - `AG` — `Оплата клієнта ✓`;
  - `AH` — `Маржу отримано ✓`;
  власнику йде коротке фінансове повідомлення.

Make.com webhook не чіпався. Усі зміни лише outbound через Telegram Bot API.

## Додатковий fix після ручного тесту

Після тестів у production-таблиці виявлено, що нові замовлення додавались у самий низ
аркуша, приблизно на рядки 999/1000, хоча видимі реальні замовлення закінчувались
на рядку 5. Причина: `sheet.appendRow(row)` враховує технічно зайняті рядки
з форматуванням, валідаціями або іншими службовими даними.

Замість `appendRow()` додано:
- `findLastRealOrderRow_(sheet)` — шукає останній реальний номер замовлення у колонці A
  за форматом `ORD-220626-012`;
- `appendOrderRow_(sheet, row)` — вставляє новий рядок одразу після останнього
  реального замовлення;
- `applyOrderRowControls_(sheet, rowNumber)` — ставить для нового рядка випадаючий
  статус у колонці C і чекбокси AG/AH.

Очікувана поведінка: якщо останнє реальне замовлення в рядку 5, наступне має
потрапити в рядок 6, а не в кінець заготовленого діапазону.

## Історичні спроби з Drive / Telegram `file_id`

У попередніх PR пробували два автоматичні варіанти:
- зберігати файл у Google Drive і давати посилання в `AF`;
- брати Telegram `file_id` після відправки власнику і потім пересилати файл
  підряднику.

Поточне рішення інше: ці автоматичні шляхи вимкнені. Не повертати `DriveApp`,
`attach_pattern_file_id`, `tg_file_<ORD>` або `sendPatternFileToContractor_()`
без окремого рішення користувача.

## Важлива зміна: автоматичне надсилання візерунку вимкнено

Після повторних проблем із Drive/Telegram fallback користувач попросив прибрати
автоматичне надсилання файлу візерунку підряднику. Поточна логіка:
- форма/Vercel і далі надсилає файл візерунку власнику в Telegram разом із
  замовленням;
- Apps Script більше не зберігає файл у Drive;
- Apps Script більше не зберігає Telegram `file_id`;
- Apps Script більше не пересилає файл у тему/групу підрядника при статусі
  `В роботі`;
- у колонку `AF` пишеться тільки примітка: файл надіслано власнику в Telegram,
  підряднику переслати вручну.

Також виправлено текст alert `contractor_failed`: він більше не стверджує, що
статус `В роботі` точно поставлено, а пише нейтрально про невдалу спробу
створити/оновити гілку підрядника.

## Fix: `AG/AH` тепер впливають на вкладку `Зведення`

Проблема: у `Зведення` рядки `Виплачено дропшиперам` / `Залишок до виплати`
рахувалися через аркуш `Виплати`, тому пташка `AH` (`Маржу отримано ✓`) ніяк
не змінювала підсумки. Для реального обліку маржі це плутало користувача:
коли клієнт оплатив підряднику (`AG=TRUE`), але маржу ще не отримано
(`AH<>TRUE`), у зведенні показувався нульовий залишок.

Зміни в `google-apps-script-v2.js`:
- `setupDashboard()` тепер рахує:
  - `Маржа до отримання (клієнт оплатив)` = `AG=TRUE`;
  - `Маржу отримано` = `AH=TRUE`;
  - `Залишок маржі до отримання` = `AG=TRUE` і `AH<>TRUE`;
  - `ЧИСТИЙ ПРИБУТОК ФАКТИЧНИЙ` = отримана маржа − комісії − витрати.
- Помісячна таблиця теж отримала колонки `Маржу отримано`, `Борг маржі`,
  `Чистий факт`.
- У меню `AVALON` додано пункт `♻️ Оновити вкладку «Зведення»`.
- Для вже існуючої таблиці після оновлення Apps Script треба один раз запустити
  `updateDashboard()` або натиснути пункт меню `AVALON → ♻️ Оновити вкладку «Зведення»`.

## Ризики / увага

- Файл візерунку тепер автоматично приходить тільки власнику в Telegram.
- Підряднику файл треба пересилати вручну.

- Власницькі статусні повідомлення працюють лише якщо в Apps Script є `TG_OWNER_CHAT` або legacy `TG_CHAT`.

## Окремий розрахунок верхньої кришки — 03.07.2026

- Верхня кришка більше не входить у штучну середню ціну за квадратний метр.
- Площа кошика: `ширина × висота + 2 × глибина × висота`.
- Площа кришки: `ширина × глибина`.
- Кошик рахується за чинним тарифом конструкції: `2030 ₴/м²` для суцільного
  або `2170 ₴/м²` для розбірного (з чинними доплатами за тип/візерунок).
- Кришка завжди рахується окремо за `1920 ₴/м²`.
- У Telegram показуються два окремі рядки: площа, тариф і сума кошика; площа,
  тариф і сума кришки. Загальна виробнича вартість є сумою цих двох частин.
- Apps Script при ручній зміні розмірів або конструкції застосовує ту саму
  розділену формулу; у фінансових колонках таблиці зберігаються загальні суми.

# Оновлення 18.07.2026: захист форми від порожніх полів

Сьогодні двічі блокувало відправку заявки помилкою
`undefined is not an object (evaluating 'form.contact_email.trim')`. Причина —
поле використовувалось у коді, але не мало дефолта в `baseForm`, тож
`form.<поле>.trim()` падав.

Щоб цей клас помилок не повторювався з будь-яким новим полем, у
`public/index.html` додано хелпер:

    const sv = value => String(value === undefined || value === null ? "" : value).trim();

Усі 32 виклики `form.<поле>.trim()` у `CatalogOrderForm` замінено на
`sv(form.<поле>)`. Тепер відсутнє поле дає `""` замість падіння форми.

Legacy-компонент `OrderForm` не чіпався — він мертвий код (у `root`
монтується лише `CatalogOrderForm`) і буде прибраний окремо.

Перевірено: JSX компілюється Babel 7.26.4 (тим самим, що на проді);
`sv()` коректно обробляє undefined/null/число/пробіли.
