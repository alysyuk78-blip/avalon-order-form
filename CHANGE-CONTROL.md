# Як безпечно замовляти зміни

## Просте правило

Не має значення, у якому чаті ви почали розмову. Безпечний чат повинен відкрити
цей GitHub-репозиторій, прочитати правила та працювати через Pull Request.

## Що не робити вручну

- не копіювати код у Google Apps Script;
- не змінювати токени у Vercel або Apps Script за порадою нового чату;
- не давати новому чату Google/Vercel/GitHub-доступ до прочитання правил;
- не погоджувати прямий push у `main`;
- не видаляти тригери, deployment або аркуші без резервної перевірки.

## Доступ до Google Apps Script

`clasp` не повинен залишатися авторизованим постійно. Перед дозволеним
deployment власник підтверджує Google-вхід, а після завершення агент виконує
`clasp logout`. Тому новий або сторонній чат не зможе самостійно змінити Apps
Script за старою авторизацією.

## Текст для нового чату

```text
Проєкт: https://github.com/alysyuk78-blip/avalon-order-form

Перед роботою відкрий репозиторій і прочитай AGENTS.md, CLAUDE.md,
CODEX-HANDOFF.md, CHANGE-CONTROL.md та DEPLOY-CHECKLIST.md.
Працюй лише в новій гілці від origin/main через Pull Request.
Не змінюй production, Vercel, Google Apps Script, Telegram або секрети без
мого окремого підтвердження після перевірок.
```

## Який звіт вимагати після роботи

- посилання на Pull Request;
- перелік змінених компонентів;
- результати тестів;
- чи змінювався production;
- номер Apps Script version, якщо був deployment;
- підтвердження, що `CODEX-HANDOFF.md` оновлено.

Якщо цього звіту немає, зміна не вважається завершеною.
